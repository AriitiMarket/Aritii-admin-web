POTENTIAL ISSUES / OBSERVATIONS
-------------------------------
1. **Dual shop route implementations** - Shops can be accessed via:
   - /admin/shops (via commerce adminPlatform routes) - used by adminApi.getShopsPaged
   - /shop/admin/shops/* (via commerce shops routes) - used by commerceAdmin methods
   Both go to commerce service but different route handlers. Both appear intentionally used for different purposes based on admin.ts comments. Response shapes seem compatible.

2. **Environment config** - Admin web .env.development uses VITE_API_GATEWAY_URL=http://localhost:3000/api while gateway defaults to port 8000. This is environment-specific config, not a code integration issue.

3. **Response envelope handling** - Backend uses ok()/fail() helpers returning {success, message, ...data}. Admin web expects this structure and accesses fields directly. Consistent.

4. **ID field normalization** - Admin web handles both _id and id from MongoDB documents. Backend returns _id from MongoDB; admin web normalizes. Correct defensive coding.

5. **Review mapping** - Admin web correctly maps reviewId to id (comment in admin.ts explains this). Backend returns reviewId in DTO. Correct.

6. **Order status filtering** - Admin web passes status, converts dates to from/to. Backend expects from/to. Correct mapping.

All route mappings, HTTP methods, and data contracts appear consistent between admin web and backend microservices. No obvious integration bugs found.
